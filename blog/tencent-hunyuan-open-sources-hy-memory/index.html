Tencent Hunyuan Open-Sources Hy Memory 2.0 Agent Architecture

The three-tier release includes the Hy Memory framework, a dedicated 30B write-path model, and MemHub for cross-agent synchronization.

In short

  • Hy Memory 2.0 introduces dedicated working memory and coding memory pipelines, moving beyond conversational chat storage.
  • Tencent released the Hy-Memory GitHub repository (containing the Python SDK and MemHub) under the Apache 2.0 license, alongside the Hy-Memory-30B-A3B model.
  • Hy-Memory-30B-A3B, a mixture-of-experts model with roughly 3 billion active parameters, scored an average of 55.49 across four memory harnesses, surpassing Claude Opus 5 and DeepSeek V4.1 Flash on Tencent's benchmark matrix.
  • The framework incorporates diff-chain version tracking for code revisions, isolating software engineering state while recording reusable problem-solving experiences.

Tencent Hunyuan has released and open-sourced Hy Memory 2.0, updating its cognitive memory stack for artificial intelligence agents by introducing dedicated working memory and code memory pipelines. Published under the Apache 2.0 license in mid-October 2026, the release transitions the platform from a theoretical framework into a three-layer open-source ecosystem consisting of a Python SDK, a specialized 30-billion-parameter memory-writing model, and a local cross-application memory hub.

According to Tencent Hunyuan's GitHub repository, the 2.0 architecture addresses a persistent bottleneck in autonomous AI workflows: the tendency of long-horizon agents to lose context across interleaved tasks, overwrite valid prior solutions, and waste context window budget on redundant transcripts. The new release organizes persistent memory into three distinct operational scenarios: chat, working, and coding.

A Three-Layer Open-Source Architecture

Unlike conventional retrieval-augmented generation (RAG) setups that rely on raw vector indexing, Hy Memory operates across three independent tiers that can be deployed individually or linked into a unified pipeline, according to Tencent's official portal.

The foundation rests on the model layer with Hy-Memory-30B-A3B, a mixture-of-experts model with approximately 3 billion active parameters hosted on Hugging Face. This model acts exclusively as a persistent memory writer. Rather than generating user responses, it executes the write path by extracting facts, reconciling conflicting records, and updating memory stores.

Above the model sits the framework layer, distributed as the hy-memory Python SDK via PyPI. The framework contains routing engines, database storage abstractions for vector and graph stores—including ChromaDB, Kuzu, Qdrant, FAISS, and Neo4j—and dual-process memory evolution logic.

The user-facing tier is MemHub, a local-first application provided as a command-line interface and macOS software. MemHub imports and synchronizes session histories across ten distinct coding and agent environments, unifying fragmented interaction traces into a governed, local directory.

Chat, Working, and Coding Memory Pipelines

The central structural development in Hy Memory 2.0 is the partition between three operational task scenes: Chat, Working, and Coding. Each task scene employs a distinct storage format and lifecycle policy.

Chat Memory Hierarchy

Chat memory focuses on long-term personal context. Building on research accepted at EMNLP 2026, it abstracts dialogue across an eight-layer cognitive hierarchy labeled L0 through L7. The structure organizes raw conversations into atomic facts, session summaries, mental schemas, and prospective intentions with expiration dates. Duplicate facts are merged, while contradictory personal preferences are reconciled before context reaches the inference model.

Working Memory for Productivity

Working memory tracks multi-step tasks across productivity workflows such as financial analysis, document preparation, and research. According to Tencent's technical documentation, each working session with tool calls outputs two linked layers:

  1. The Fact Layer (WorkingFact): Captures exactly one session record containing the task objective, chosen methodology, and intermediate results without requiring threshold filtering.
  2. The Experience Layer: Stores zero to multiple reusable problem-solving strategies that meet explicit confidence thresholds, complete with boundary conditions governing when the approach applies.

When an agent resumes a suspended project, the engine cross-references whether current environmental conditions match past experience boundaries before applying cached approaches.

Coding Memory and Version-Evolution Tracking

Software engineering workflows present distinct challenges for memory frameworks. Agents frequently alter the same file across multiple iterations, and naive memory systems risk surfacing discarded or broken intermediate states.

Hy Memory 2.0's Coding pipeline reuses the two-layer schema of Working memory but introduces a code version-evolution diff chain, detailed in Tencent's CMB technical benchmark. Instead of saving raw code blocks into memory banks—which rapidly exhausts token limits—the framework records exact coordinates such as file paths, functions, and Git branches, alongside a ledger of sequential modifications.

This separation prevents rolled-back code edits from appearing as active facts. If an engineering agent evaluates previous work on an issue, it queries the diff chain to inspect why specific design choices were made and which modifications were retained in the final patch.

Coding memory is stored independently from productivity data. The SDK routes coding tasks to isolated databases (coding_memory_cv.db), ensuring software traces do not pollute organizational or personal memory collections.

Hy-Memory-30B-A3B: Specialized Memory Writing

Tencent's dedicated write-path model, Hy-Memory-30B-A3B, was developed to replace general-purpose LLMs inside memory architectures. As reported in the model's technical documentation on arXiv, memory writing was optimized via a two-stage training process:

  • Memory On-Policy Distillation (OPD): The model writes memory state chains while a larger teacher model supplies dense supervision on the student's self-generated state transitions.
  • Attributed Memory Reinforcement Learning: The training harness inspects resulting memory banks across rollouts, assigning credit at the individual chunk level rather than scoring whole conversations. Credit normalization identifies the strongest memory updates per chunk, propagating the top bank forward into subsequent task windows.

In Tencent's comparative evaluations across four memory testbeds (Mem0, Hy-Memory, MemOS, and the held-out EverMemOS), Hy-Memory-30B-A3B achieved a macro-average score of 55.49 across a fixed 20% benchmark subsample. This narrowly exceeded Claude Opus 5 at 54.62 and DeepSeek V4.1 Flash at 53.64, while substantially outperforming comparable-scale open models like Qwen3-30B-A3B at 44.37.

Independent analysis from MindStudio notes that while Hy-Memory-30B-A3B secured the highest overall average, performance across individual sub-benchmarks varied. Claude Opus 5 led on raw LoCoMo judge evaluations within Mem0 and MemOS harnesses, while DeepSeek V4.1 Flash led on select code evaluations. The compact model's principal advantage lies in sustained performance across differing memory backends at an active footprint of roughly 3 billion parameters.

Local Agent Federation via MemHub

To bridge isolated development tools, Tencent bundled the framework with MemHub. As detailed by Pandaily, developers commonly define preferences and project guidelines in one coding assistant, only to repeat them when switching environments.

MemHub runs locally, interfacing with user-authorized tools including Cursor, Codex, Claude Code, OpenCode, Qwen Code, OpenClaw, WorkBuddy, Pi, Hermes, and DeepSeek Harness. When authorized, MemHub ingests historical transcripts, formats them through the hy-memory pipeline, and serves an updated memory representation back to connected tools as contextual augmentation.

Internal Deployment and Ecosystem Context

Prior to open-sourcing, Tencent deployed Hy Memory internally across its enterprise divisions, according to Tencent's official portal. Implementations span financial research in Tencent Stock (Zixuangu), team documentation via the iWiki CTX memory plugin, and interactive features in Tencent News.

In Tencent's internal investment research evaluation, migrating from legacy memory pipelines to Hy Memory produced a 23.8% relative gain in composite accuracy, increasing multi-hop retrieval rates from 50% to 90% and conflict resolution scores from 67% to 83%.

By releasing the weights, SDK, and local aggregation tools simultaneously, Tencent offers the open-source community a structured alternative to standard context-stuffing methods, which MindStudio notes demonstrates that compact, specialized models can manage memory state more efficiently than general frontier models.

Questions people ask

What is Hy Memory 2.0?

Hy Memory 2.0 is an open-source cognitive memory framework developed by Tencent Hunyuan for AI agents. Released under the Apache 2.0 license, it provides structured memory engines for chat, working tasks, and software coding.

What does the 'A3B' designation mean in Hy-Memory-30B-A3B?

The 'A3B' designation indicates a mixture-of-experts model architecture where approximately 3 billion parameters are actively engaged during any single inference call, out of a larger 30-billion total parameter count.

Which development tools are supported by MemHub?

MemHub supports 10 AI applications and coding environments, including Cursor, Codex, Claude Code, OpenCode, Qwen Code, WorkBuddy, OpenClaw, Pi, Hermes, and DeepSeek Harness.

How does Coding memory differ from Working memory in the framework?

While both use a two-layer schema for facts and experiences, Coding memory records precise coordinates such as file paths and branch names instead of raw code snippets, and maintains a version-evolution diff chain to track sequential code changes.
