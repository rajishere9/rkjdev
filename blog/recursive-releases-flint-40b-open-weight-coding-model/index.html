Recursive Releases Flint 40B Open-Weight Coding Model for Laptops

Built with an automated research system according to Recursive, the 40B mixture-of-experts model activates just 2.5B parameters to run high-speed agentic coding directly on local machines.

In short

  • Recursive launched Flint under an Apache 2.0 license, featuring 39.8 billion total parameters and approximately 2.5 billion active per token.
  • According to Recursive, the model was built in under four months using its automated research harness, known as the Eureka Machine.
  • Flint runs locally on 48 GB Apple Silicon Macs and NVIDIA RTX Spark systems, achieving generation speeds above 125 to 150 tokens per second.
  • On benchmarks reported by Recursive, Flint achieved 74.2% on SWE-bench Verified and 89.7% on SWE-bench Pro v2.

On October 21, 2026, AI research startup Recursive released Flint, its first open-weight model designed for autonomous software development and local code execution. Available under an Apache 2.0 license on Hugging Face, the text-only decoder Transformer contains 39.8 billion total parameters while activating approximately 2.5 billion parameters per token. The architecture is engineered to run directly on consumer workstations and laptops, allowing developers to inspect repositories, resolve bugs, and run tool-assisted coding workflows offline without sending proprietary source code to third-party cloud servers.

According to Recursive, the company developed Flint in under four months by using an internal system dubbed the Eureka Machine, led by Chief Executive Officer Richard Socher. According to reporting by TechCrunch, the startup, which came out of stealth in May 2026 with $650 million in funding from backers including GV, NVIDIA, and AMD Ventures, said it used the automated harness to search architectures, devise quantization strategies, and write specialized hardware compute kernels.

Automated Design via the Eureka Machine

Recursive describes the Eureka Machine as an automated research engine that proposes technical hypotheses, implements code, runs experiments, and selects next steps based on empirical results. Rather than relying solely on human engineers for iteration loops, Recursive put the automated agent directly into the model design pipeline, as documented in an announcement on the Recursive company blog.

Recursive highlighted three structural contributions made by the automated harness to Flint's release. First, it initiated architecture searches from a 35-billion total, 3-billion active baseline, testing varied expert configurations and layer widths before selecting a sparse mixture-of-experts layout with 40 billion total parameters and 2.5 billion active parameters. Second, the system applied 4-bit quantization to the model's output projection layer—a layer traditionally preserved at higher bit-widths—and recovered accuracy by using an offline distillation pass with the 16-bit model acting as a teacher. Third, the system generated custom computational kernels, including a fused Metal megakernel for Apple Silicon decode passes.

Socher told WIRED, as reported by Superpower Daily, that while recursive self-improvement remains the company's long-term research roadmap, Flint itself is not an autonomously runaway system. Socher emphasized that the platform operates under administrative human supervision.

Architecture Specifications and Local Hardware Targets

Flint features a 49-layer decoder design composed of two initial dense layers followed by 47 mixture-of-experts layers. Each MoE layer maintains 256 routed experts, selecting six routed experts per token alongside one constantly active shared expert. The model includes an attention setup of 35 sliding-window layers across a 513-token window and 14 full-attention layers without positional encodings, as detailed on the official model card.

The official configuration specifies a context window of 262,144 tokens, while Recursive's blog states Flint supports context windows of up to 512k tokens (recommending staying within 256k for best results). Quantized 4-bit weights consume approximately 23 gigabytes of local storage and memory, making the model compatible with Apple M4 Pro, M5 Pro, and M5 Max systems equipped with 48 gigabytes of unified memory, as well as 48-gigabyte NVIDIA systems.

Recursive reports short-context decode speeds surpassing 125 tokens per second on an M4 Pro MacBook Pro and over 150 tokens per second on an NVIDIA RTX Spark device. At GTC Berlin, NVIDIA announced day-zero platform support for Flint across its RTX Spark and DGX Spark platforms, enabling developers to run and fine-tune Flint using the NeMo ecosystem via low-rank adaptation and reinforcement learning.

Benchmark Performance and Limitations

In evaluations published by Recursive and compiled by MarkTechPost, Flint scored 74.2% on SWE-bench Verified, 89.7% on SWE-bench Pro v2, and 54.9% on Terminal-Bench 2.1 in its 16-bit BF16 checkpoint. The 4-bit NVFP4 quantized checkpoint produced comparable marks, recording 74.1% on SWE-bench Verified, 88.5% on SWE-bench Pro v2, and 53.7% on Terminal-Bench 2.1.

On instruction-following and synthetic evaluations, Flint reached 95.1% on IFEval and 80.3% on LiveCodeBench v6. Recursive's internal evaluations placed Flint above other sparse models under 50 billion parameters, including Qwen 3.6 MoE and Laguna XS 2.1. However, the model trailed larger dense baselines on terminal automation; for example, Alibaba's dense Qwen 3.8 scored 73.0% on Terminal-Bench 2.1 compared to Flint's 54.9%.

Recursive noted that while Flint excels at handling multi-turn tool calling and codebase exploration, it recommends breaking complex tasks into smaller subtasks. Because extended agentic reasoning can rapidly consume token allowances, Recursive recommends deploying an output budget of at least 32,768 tokens for complex coding problems.

Questions people ask

What is Recursive Flint?

Flint is an open-weight, 39.8-billion-parameter mixture-of-experts coding model developed by Recursive Superintelligence. It activates approximately 2.5 billion parameters per token and is designed to execute locally on laptops and workstations.

What hardware is required to run Flint locally?

Flint's 4-bit weights require roughly 23 GB of memory. It runs on Apple Silicon Macs (M4 Pro, M5 Pro, or M5 Max) with at least 48 GB of unified memory, as well as 48 GB NVIDIA GPUs and systems like the NVIDIA RTX Spark and DGX Spark.

What license is Flint released under?

Flint's weights and code artifacts are available under the open-source Apache 2.0 license.

How does Flint compare to dense coding models?

According to Recursive, Flint delivers coding scores comparable to dense 25B to 40B models while running more than five times faster due to its sparse activation of 2.5B parameters per token. However, it trails some large dense models, such as Qwen 3.8, on specific terminal execution benchmarks.
